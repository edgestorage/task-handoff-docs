# 仓库协作

当会话工作目录位于 Git worktree 中时，实例页面会显示仓库环境入口，用于查看文件、变更、worktree、分支和远端同步。所有操作都在该受控实例内执行。

## 文件

“文件”区域可以浏览仓库目录，并打开、编辑、新建、重命名或删除文本文件。以下内容不会作为普通文本打开：

- `.git` 内部内容或超出工作区边界的路径；
- 二进制文件、特殊文件和超过大小限制的文件；
- 逃逸工作区的符号链接；
- submodule 或嵌套仓库的内部内容。

如果 AI、终端或其他编辑器在你打开文件后修改了它，保存会因版本过期而停止。先比较服务端新版本和当前草稿，再选择采用服务端内容或明确重试。

## 变更

“变更”按冲突、已暂存、未暂存和未跟踪分类。同一文件的 staged 与 unstaged 差异可能不同，应分别检查。

支持的安全操作包括：

- Stage / Unstage 指定文件；
- 丢弃指定 tracked 文件的工作区修改；
- 丢弃指定 tracked 文件的全部已暂存与未暂存修改；
- 只提交当前 index 中的内容。

::: danger 丢弃操作
丢弃修改不可撤销。TaskHandoff 不会自动创建 stash，也不会删除未跟踪文件。确认前检查选中的路径和操作范围。
:::

## Worktree 和分支

托管 worktree 由 TaskHandoff 创建，可以安全地用于新 AI 会话。外部 worktree 只有位于实例授权目录且仍可访问时才能使用，系统不会接管或删除它。

删除托管 worktree 前，它必须是非主工作树、无修改、未锁定，并且没有活跃的 AI 或应用会话。删除工作树目录后，关联 Git 分支会保留。

分支操作不会自动 stash 或强制覆盖。如果目标分支已被其他 worktree 使用、存在未合并提交或切换会覆盖修改，操作会被阻止。

## 拉取与推送

TaskHandoff 采用保守的远端操作：

- Fetch：只更新所选远端跟踪引用；
- Pull：仅允许 fast-forward，不自动 merge、rebase 或 stash；
- Publish / Push：需要明确选择本地来源、远端和目标分支；
- 分支已分叉时：阻止自动同步，需要在终端中手动处理；
- 永远不执行 force push。

远端认证失败时，进入“实例设置 → Git 凭据”检查授权，保存后手动重试。系统不会自动重放失败的写操作。

## 何时使用终端

以下操作建议在对应会话的终端中完成，然后刷新仓库页面：

- 解决复杂冲突或选择 merge/rebase 策略；
- 处理已分叉分支；
- 查看大型或二进制 diff；
- 调试 Git hook、提交签名、SSH 或凭据问题；
- 执行界面没有提供的高级 Git 命令。
