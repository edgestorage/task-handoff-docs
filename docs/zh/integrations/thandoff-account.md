# 通过 Thandoff 账户访问

Thandoff 账户可以把一台自管 Control Plane 发布到账户目录，并通过后台中转供移动端等已授权客户端访问。同一个账号还可以绑定 Node Agent，让账号内的其他 Control Plane 通过云中继使用这些节点。两端都主动出站，因此这条路径不需要开放公网入站端口。

中转内容包括客户端到 Control Plane 的 API、响应流和 WebSocket，以及账号内 Control Plane 到已绑定 Node Agent 的节点通道。云端中继只处理密文帧、路由和计量标识，不保存明文请求、AI 会话、文件或终端内容。节点仍需要单独批准 Control Plane 信任。

## 绑定 Control Plane

只有本地管理员可以修改账户连接：

1. 在本地或可信网络中打开“设置 → Thandoff 账户”。
2. 记录页面显示的 Control Plane ID 和身份指纹。
3. 选择“连接 Thandoff 账户”。系统会打开授权页面，并把一次性授权码复制到剪贴板。
4. 在授权页面登录目标账户，核对 Control Plane ID、指纹和授权码后确认。
5. 返回设置页，确认状态为“已连接”，且后台中转显示“已安装专用凭证”。
6. 在移动端登录同一个 Thandoff 账户，从 Control Plane 目录添加该面板，并再次核对身份指纹。

一次性授权码约 5 分钟内有效，且消费后立即失效。授权未完成或已经过期时，回到设置页重新发起，不要继续使用旧页面中的授权码。

## 账户登录与设备安全

Thandoff 账号支持邮箱与密码、Google/GitHub/Apple 登录、邮箱验证、TOTP 与一次性恢复码，以及 Passkey。账号设置可以登记多个 Passkey，并查看每个 Passkey 的创建时间和最近使用时间。

- 修改密码、管理 TOTP 或 Passkey、注销账号等敏感操作需要最近身份验证；验证通过后的短时间内可以继续执行敏感操作；
- “已登录设备”列出该账号的登录会话，可以单独撤销丢失或不再使用的设备；
- Thandoff 账号登录设备与 Control Plane 的“移动设备会话”和云中继“已信任设备”是不同边界。前者管理账号身份，后两者分别控制 Control Plane 登录和固定到该 Control Plane 的云中继访问；
- 退出账号会移除该账号添加的云端 Control Plane，手动添加的直接连接会保留。

完整的客户端能力见[移动端](/zh/clients/mobile#云账号与安全)。

## 后台运行方式

中转由 Control Plane 后台进程持有，不依赖发起授权的浏览器页面。以下操作不会停止中转：

- 关闭“Thandoff 账户”设置页；
- 退出本地 Web UI；
- 关闭或让授权浏览器会话过期。

停止 Control Plane 服务、关闭远程访问、撤销绑定或发生身份冲突会终止中转。服务恢复后，只要绑定仍有效且远程访问已开启，后台进程会使用专用凭据重新连接。

## 云平台节点

节点绑定到账号后，可以作为“云平台节点”供同一账号内的其他 Control Plane 使用：

1. 在已经管理目标节点的 Control Plane 中打开节点详情。
2. 进入“云平台节点”，选择“添加到云平台”。
3. 在需要接入的 Control Plane 中打开“添加节点”，选择“使用云平台中转”。
4. 选择账号中的已有节点，或生成命令安装并绑定新的 Node Agent。
5. 在节点侧核对比较码并批准 Control Plane 信任。

添加节点不会改变它原来与当前 Control Plane 的连接，也不会迁移实例。账号中的共享节点使用权可能带过期时间；过期或撤销后，依赖该授权的 Control Plane 不能继续建立新连接。

节点详情会显示云平台通道状态、最近中转错误和已信任的 Control Plane。当前 Control Plane 不能在同一个界面撤销自己的信任，需要在节点上运行 `task-handoff-node-agent trust` 命令；其他 Control Plane 可以直接撤销。完整连接流程见[连接远程节点](/zh/integrations/remote-nodes#通过-thandoff-账号中继)。

## 数据区域与中继边界

Thandoff Cloud 使用单一主数据区域（home data region）保存账号、绑定、共享、审计和计量记录，不做跨区域复制或自动故障转移；该区域可能位于你所在国家或地区以外。Relay 数据面可以部署在其他区域，但只临时转发加密流量，不在磁盘上保存会话内容。

云端会处理账号、登录设备、连接时间、路由和流量等运行所需信息。工作区中的 AI 对话、代码、文件和终端内容通过端到端加密传输；云端可以中断或延迟连接，但无法读取这些内容的明文，也不能替管理员批准设备。

通过云中继的远程工作本身免费。中继流量额度只用于防止滥用、欺诈或服务中断；合理使用超出额度时，可以在合理范围内免费提升。自托管部署不依赖 Thandoff Cloud，也不受云中继额度影响。

## 状态说明

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 未连接 | 没有有效账户绑定 | 发起连接 |
| 等待授权 | 已创建一次性授权挑战 | 在过期前完成授权，或重新发起 |
| 已连接 | 绑定有效 | 根据需要开启或关闭远程访问 |
| 等待撤销 | 本地已关闭，但远端撤销结果未确认 | 恢复网络后重试断开，不要绑定第二个账户 |
| 身份冲突 | 另一安装正在使用同一 Control Plane 身份 | 先确定哪个安装保留原身份 |

页面中的“绑定 revision”用于识别账户侧授权版本；客户端访问时还会校验 Control Plane ID、账户、绑定 ID 和 revision。旧的或已撤销的授权不能继续建立新连接。

## 关闭与断开

“关闭远程访问”和“断开 Thandoff 账户”含义不同：

| 操作 | 保留账户绑定 | 停止中转 | 后续恢复 |
| --- | --- | --- | --- |
| 关闭远程访问 | 是 | 是 | 选择“开启远程访问” |
| 断开 Thandoff 账户 | 否 | 是，并撤销节点中转授权 | 重新完成绑定授权 |

关闭远程访问时，本地停用立即生效；如果远端结果暂时未知，界面会提示该状态。断开账户会先把状态置为等待撤销并关闭连接，再向账户服务撤销绑定。远端撤销未确认前，本地不会允许绑定第二个账户，以免产生两个权威绑定。

## 处理身份克隆冲突

Control Plane 的 ID 和签名身份保存在其数据目录中。直接复制整个数据目录并同时运行原安装和副本，会让两台机器以同一身份上线。账户服务检测到这种情况后，会把状态置为“身份冲突”、删除后台中转凭据并隔离所有远程数据连接。

不要通过反复点击“开启远程访问”绕过冲突。应先停止其中一个安装，确定哪台机器保留原 Control Plane 身份，再让副本使用新的数据目录建立新身份并重新配置。恢复前核对备份和 DNS 指向，避免把生产身份误留在临时副本。

## 安全检查

- 只在可信的本地管理员会话中发起绑定或断开操作。
- 为 Thandoff 账号启用 TOTP 或 Passkey，并定期审查“已登录设备”和 Control Plane 的云中继“已信任设备”。
- 在授权页和移动端同时核对 Control Plane ID 与身份指纹。通过云中继访问时，固定指纹、设备私钥签名和本地批准必须同时通过。
- 丢失移动设备时，同时撤销 Thandoff 账号中的该登录设备，以及 Control Plane 的移动设备会话；普通设备丢失不需要轮换 Control Plane 身份。
- 账户异常、后台凭据被撤销或远程访问被关闭时，已有中转连接也应随之关闭。
- Thandoff 账户中转不能替代 Control Plane 自身的用户、角色和节点/实例访问范围控制。
- 云平台节点首次连接、Control Plane 公钥变化或访问上下文变化时，必须在节点侧核对比较码后重新批准信任。
