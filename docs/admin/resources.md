# 模型、镜像与项目

全局设置中的资源库决定创建实例时可以选择什么。模型、镜像、环境模板和项目各有不同所有者与生命周期。

## 模型

模型连接可以属于 Control Plane，也可以只保存在某个节点。支持的上游协议包括：

- `openai-responses`：主要用于 Codex；
- `openai-chat-completions`：主要用于 OpenCode；
- `anthropic-messages`：兼容 Claude 配置。

一个连接可以列出多个模型名称并调整顺序。保存前使用“发现模型”和“测试”检查端点、凭据和延迟。停用模型后不能用于新选择，但已有引用会保留为待处理状态。

## 镜像

“镜像市场”是只读目录；“自定义镜像”由管理员维护。自定义镜像必须使用规范的 OCI 引用。删除记录不会自动删除节点上的 Docker layer，被项目、节点目录默认值或实例引用时也会被阻止。

创建实例时会保存镜像快照和最终 digest，因此市场 tag 后续变化不会悄悄改变现有实例的环境事实。

## 环境模板

环境模板由某个节点从 Docker 实例创建，并与该节点上的实际镜像绑定。只有模板所属节点在线且镜像存在时才能使用。

模板捕获容器可写层，不包含工作区和数据卷。删除模板会移除模板入口；仍被派生实例引用的底层镜像会保留，最后一个引用消失后才可回收。

## Git 项目

Git 项目保存仓库 URL、名称、可选默认镜像和凭据引用，用于快速创建实例。项目记录不是仓库内容的副本。

项目被实例或默认配置引用时，界面会显示“使用中”。删除前先检查引用。私有仓库应使用托管凭据，不要把 Token 写进 Git URL。

## 节点本地项目

本地项目引用特定节点上的目录，只能在该节点创建实例。它适合已有源码或大型本地数据，但隔离程度取决于所选运行时和目录权限。
