# 更新与版本

TaskHandoff 的 Control Plane、Node Agent 和 Controlled Instance 可以独立运行，但服务器发布会把兼容版本作为一个版本集管理。

## 发布渠道

| 渠道 | 用途 |
| --- | --- |
| stable | 生产环境默认选择 |
| beta | 验证接近稳定的新功能 |
| alpha | 早期测试，可能频繁变化 |

切换渠道是明确操作，预发布版本不会自动成为稳定更新。

## 服务器更新

完整服务器安装可在“设置 → 基础 → 服务端更新”执行，也可使用：

```sh
task-handoff check
sudo task-handoff update
```

更新器保留服务用户、端口、数据目录、IPC 和认证模式，先恢复 Node Agent，再启动并检查 Control Plane。持久化迁移失败不会自动回滚数据，应先备份。

## 节点更新

在“设置 → 节点 → 更新”选择渠道、检查版本并启动 rollout。更新任务会预检平台 artifact 和 launcher 兼容性，再重启 Node Agent。

更新后的 Node Agent 会让运行中实例收敛到目标 runtime。活跃任务获得有限排空时间，超时后实例仍可能重启；停止的实例不会为更新而启动，而是在下次启动前安装。

## 桌面更新

桌面端使用独立发布渠道和安装包。更新会重启桌面应用及其服务，不由服务器更新页面管理。

## 更新前检查

- 查看运行中的 Codex/OpenCode 会话和终端；
- 提交或备份未保存修改；
- 记录当前版本和渠道；
- 备份 Control Plane 数据目录；
- 确认节点有足够磁盘空间和外网/镜像源访问。

## 更新失败

保存更新任务的结构化错误和版本信息。不要直接删除实例或数据目录。先恢复 Node Agent 服务和控制面板访问，再按错误提示重试 artifact、实例 reconcile 或重新安装原版本。
